# Plan-configured campaign ownership adapter

These three new operational files adapt the accepted P20 resource-repair v002 native owner, Linux entry and LF shell without editing their original bytes. They import the new common provider and call configure_argv before reading cohort paths or counters. One immutable plan supplies1..20 inputs, per-cohort evidence/output/state paths, COUNT and the cold-session ceiling. The common/scientific provider owns selection, accepted-work exclusions, conditional qualification, scientific budgets and per-phase unit arguments.

The native request binds the exact plan and passes its Linux path/SHA and launch token explicitly through /usr/bin/env before the existing private namespace wrapper. The new shell requires exactly --input-plan PATH --input-plan-sha256 SHA, checks equality with the explicit environment and forwards all four arguments to the entry. The shell is LF-only. No WSL transport or bash execution was performed during source preparation; actual preflight must syntax-check the admitted shell bytes.

Cold accounting is dynamic:600 seconds before the helper, helper ceiling cold-1240,600 seconds for post-unmount hashing and40 seconds for cleanup. The native deadline is cold-40; the entry clips the helper to min(cold-1240, actual remaining cold-640), and passes that actual deadline to the scientific core. Consumed native startup time is deducted before the immutable wall deadline is written. The core independently clips its own phase/input/cohort allowances; these wrappers add no scientific allowance.

Exact process births, retained WSL handle outcomes, partial common-lock release, optional telemetry isolation, creation-pinned helper cleanup, ordinary read-only image/IPC closure and pre/posthash gates carry forward. Unknown/forced closure creates a handoff and blocks replay; WSL exit alone cannot prove guest closure. Required command, input, terminal and handoff evidence remains strict. The native registers standard stage04 before WSL, uses COUNT rather than a singleton counter and marks diagnostic_only false. Existing P20 protocol status literals remain for compatibility; successful native output is still pending external actual-owner exit, lease closure and Root review, with no panel acceptance.

Nine pure source fixture groups passed without importing any target operational/scientific module or starting a child. They cover typed1/19/20-row results, monotone counters, configuration order, exact unchanged guard-function ASTs, actual request/helper budget expressions, explicit transport, LF/argument shape, current ownership/unknown-handoff behavior and nonpilot counters. Their scope does not validate scientific math, the provider's selection or actual runtime performance. Root's integrated source review and separate cohort admission remain required.
