This next stage measures coverage, copy number and cross-profile ambiguity of the 281 candidates discovered in this new project. Assessing these candidates across 919 provisional proteomes does not complete full-panel marker discovery, establish orthology or admit a final marker set. Broader candidate discovery, occupancy/paralogy review, careful alignments and gene-tree validation remain necessary. The old 105-marker set and Tree1 are not inputs.

Defence calls remain UNKNOWN_UNSEARCHED.

The original closed 281-profile search covered 29,133 proteins from 14 genomes. Complete ordered amino-acid sequence comparisons find 12 proteomes exactly identical to current uniform proteins. Their closed raw domain results are reused with a bijective identifier rename; no HMM search is repeated. GCF_000518205.1 and GCF_900167405.1 differ under the uniform annotation, so they are new protein inputs. There are 907 new proteome searches and 12 exact saved-search reuses.

New searches retain the original 29,133-target **reference calibration**, explicitly using HMMER `-Z 29133`, one stock search thread, seed42, full-sequence and independent-domain E-values <=1e-5, union HMM coverage >=0.7 and union target coverage >=0.5. The pinned HMMER manual documents `-Z` as the asserted target count. The default conditional-domain reporting count remains local; conditional reporting cannot discard a domain satisfying the stricter independent-domain bound. These are E-values against a fixed reference search space, not an assertion that the full919 database contains only29,133 proteins or a family-wise error correction over all919. This keeps saved and new scores on the same declared scale. Production marker acceptance needs separate orthology evidence and review.

Each successful genome commits the raw-search execution and domains, qualifying hits, all281 profile copy counts and every protein qualifying against more than one profile. Ambiguous proteins are retained with their alternatives; score ranking does not silently assign an ortholog. Zero means no qualifying hit in an actual completed search under this policy. Failed, unsearched and inconclusive work stays UNKNOWN. Complete predicted defence systems require their own pinned searches and coordinate checks.

One persistent native owner runs the entire serial queue through the reviewed detached launcher. Both native and Linux owners use CPU2, with one search thread. A failed unit stops the queue, preserving all saved results, attempts, debits and actual exits. There is no automatic scientific retry.
