# Useful live monitor - V5

The visible PowerShell monitor keeps the table layout and removes the single0/1full-tree counter, oldQC cards, repeated policy text and historical failure clutter. It refreshes every30seconds without changing the analysis.

The current-work table shows the actual IQ-TREE phase; exact-process CPU activity; wall and CPUtime; last reported search improvement; best likelihood and improvement since the initial fit; bootstrap/SH-aLRT state; measuredRAM against its allocation; Linux free-memory headroom; checkpoint age and log age. A compact second table shows completed, current and queued project stages, and follows later published stages.

CPU is measured from the real Linux IQ-TREE process through read-only filesystem access. The monitor verifies the boot, driver and child creation identities and exact command line; it does not mistake the idle Windows wrapper for the scientific process. No WSL helper, new collector daemon or scientific command is started for refreshes.

The current20initial candidates are a scheduled candidate set, not a completed-work denominator. Last reported improvement at iteration4 does not mean4of20finished. Likewise, preparation of1,000 bootstrap samples does not mean1,000 support calculations are complete. Adaptive search has no reliable whole-run percentage or ETA, so none is fabricated.

An old log or checkpoint is shown with its actual age. Live CPU activity is shown separately because long optimization can continue between log/checkpoint writes. Checkpoints are inspected by file metadata only; the monitor never edits or hash-accepts an active checkpoint.
