# Scaler compatibility and one matching-version route

Reviewed 2026-10-26/27. The completed model-loading smoke proves that the original payload loads. It does not validate cross-version inference. Actual stderr reports the MinMaxScaler serialized by scikit-learn1.6.1 being loaded by1.9.1. Production QC remains `SCALER_COMPATIBILITY_UNVALIDATED`; a numeric one-genome result cannot remove this gate.

## Evidence and decision

Both scikit-learn1.6 and current documentation explicitly exclude support for loading persisted estimators under a different scikit-learn version, even when deserialization succeeds. Matching the saved library version removes this known mismatch; it does not reconstruct the entire original training environment, whose other dependency versions are not established. [Persistence documentation](https://scikit-learn.org/1.6/model_persistence.html)

Static pickle-opcode inspection, without unpickling, confirms saved version1.6.1,21,241 features, range(0,1), copyTrue and clipFalse. Original CheckM2 code casts dense feature vectors to float, scales all21,241 columns and sends the first20,021 scaled features to the neural model after channel reshape. It passes the full scaled vector to postprocessing, whose cosine implementation internally crops it to the first20,021 columns. General boosting separately uses all21,241 unscaled features. Preserved source and control hashes are recorded in `evidence/checkm2_runtime/scaler_static_compatibility_review.json`. Data/model integrity is independently bound by the accepted official package SHA; it is separate from runtime compatibility.

The official bundled `testrun` is an integration smoke, not a numerical regression test: pinned `main.py` lines240–266 checksum-check the three controls, predict, and print success when the result has more than one row. It asserts neither exact three names nor expected numerical estimates. Its success message/exit code cannot establish inference equivalence.

## Concrete primary strategy: immutable base plus one official wheel overlay

The one acquired file is `scikit_learn-1.6.1-cp312-cp312-manylinux_2_17_x86_64.manylinux2014_x86_64.whl`,13,147,700 bytes, SHA256 `2e69fab4ebfc9c9b580a7a80111b43d214ab06250f8a7ef590a4edf72464dd86`. Official PyPI metadata identifies CPython3.12/x86_64/glibc2.17+ compatibility and these runtime floors: Python3.9, NumPy1.19.5, SciPy1.6.0, joblib1.2 and threadpoolctl3.1. The existing base has Python3.12.16, NumPy2.5.4, SciPy1.18.1, joblib1.6.0 and threadpoolctl3.7.0, satisfying those declared floors. [Exact official release and file](https://pypi.org/project/scikit-learn/1.6.1/)

The worker verified source metadata, exact archive bytes/SHA, wheel identity/tags, ZIP CRC, every RECORD entry, all member paths/types and native ELF requirements before atomic directory publication. The complete unchanged payload is894 files/41,470,241 bytes, including69 ELF members; maximum observed required GLIBC is2.17. Original scikit-learn/liblinear notices and the bundled GCC runtime exception remain in their source locations. The wheel and metadata are preserved in `tools/sklearn161_overlay_sources/`.

The complete overlay is `tools/sklearn161_overlay/site-packages/`. Its894-file manifest is `tools/sklearn161_overlay/manifest.json`, SHA256 `bf8283a183f42f5f06dce5b88bf37e508c2d1d6ed0d9814749e4a8761c6936c7`. `evidence/checkm2_runtime/sklearn161_effective_runtime.json` explicitly binds the immutable base image/candidate/model manifests, wheel, overlay files,133 effective package identities and exact environment. The installed base1.9.1 files/metadata remain present and are explicitly shadowed. No pip, solver, dependency installation or base-image write occurred.

Set PYTHONPATH to the single exact overlay site-packages path, retain PYTHONNOUSERSITE and disabled bytecode, and privately bind the overlay read only. Python's isolated mode ignores PYTHONPATH, so an overlay launch must not accidentally use `-I`/`-E`. [Python environment rules](https://docs.python.org/3.12/using/cmdline.html#envvar-PYTHONPATH)

Crucially, bare PYTHONPATH is insufficient for the real CheckM2 CLI: unchanged upstream `main.py` prepends its own base site-packages before importing model code. A reviewed launch bootstrap must first preload and verify overlay sklearn1.6.1 and its package search path, then execute the unchanged original entrypoint and recheck submodule origins after the upstream prepend. Generic distribution discovery may still see base1.9.1 metadata first; record that fact and read the effective distribution metadata directly from the pinned overlay dist-info path. Never rewrite upstream source, change pickle version fields, suppress warnings or claim base metadata was replaced.

This is currently a statically prepared candidate, not an accepted runtime. Tags/dependency floors and ELF requirements do not prove all native/NumPy/OpenMP behavior. The wheel includes its own hashed libgomp beside the base runtime's libraries; the owner must inspect actual loaded threadpool/library paths and enforce the existing thread/resource bounds. NumPy documents forward ABI compatibility within a major release, with a major-version break at2.0; native compatibility still requires testing this exact artifact and effective stack. [NumPy downstream ABI guidance](https://numpy.org/doc/stable/dev/depending_on_numpy.html)

## Required validation before production consideration

1. Under the proven private namespace, read-only base image/overlay and existing2-thread/2GiB-RSS/1GiB-headroom limits, verify effective sklearn1.6.1, all relevant module/extension origins, explicit overlay metadata, all nine original model assets and immutable bindings. Any inconsistent-version warning, mixed sklearn package path, native failure or unexpected origin holds the gate. Preserve all emitted warnings.
2. Independently check the actual saved MinMaxScaler state and its full21,241-column transform. Use a small fixed float64 matrix covering zero, one, saved minima/maxima, interior and out-of-range values, and fixed-seed heterogeneous rows. Compare against an independently written scalar affine reference using the saved scale_ and min_, retaining clipFalse and exact column order. Require identical finite masks/shapes and a predeclared strict numerical criterion; do not choose tolerances after seeing differences. Test malformed widths and invalid infinities as rejected inputs. This characterizes the scaler arithmetic; synthetic rows are not biological validation.
3. Exercise the unchanged neural slice/reshape, general/specific model outputs, cosine similarities and model-selection boundary decisions under controlled fixtures. Preserve the full21,241-column scaler/general interface, and separately verify the20,021-column neural/cosine crop. Successful deserialization or finite neural output alone is insufficient.
4. After resource admission, independently validate all three checksum-bound official control inputs with exact expected names, finite schema and a predeclared version/database-matched numerical reference and tolerance. Preserve inputs, feature vectors, model choices, outputs and warnings. Do not treat the upstream row-count test, unrelated NCBI CheckM estimates, or an unsupported1.9.1 run as ground truth. If no trustworthy numerical reference is available, state that limitation and keep production acceptance unresolved.
5. Only a reviewed supported effective stack plus these controls, a passing bounded source-genome resource pilot and measured representative batch can be considered for production. Methodological QC and per-genome95/5 screening remain separate; missing/failed predictions never become negatives.

Passing a few affine/control comparisons under1.9.1 would not make that cross-version pickle usage supported. The chosen route instead removes the known scikit-learn version mismatch while preserving the established base. If its bounded native/import/interface validation fails, stop and retain evidence. One separately reviewed matching Conda environment/image is the bounded fallback; it must preserve the current immutable base and reuse accepted archives. No alternate wheel, install, solve, import, mount or prediction is authorized by this review itself.
