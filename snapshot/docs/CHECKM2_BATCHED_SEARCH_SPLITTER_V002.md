# Future merged-search splitter V2

This is standalone SOURCE PREPARATION ONLY. It is not connected to the active serial V1 campaign and creates no new scientific admission, search, model run or queue claim. No performance, memory-fit or numerical equivalence has been established for merged searches.

`split_search` accepts SHA256/size-bound references to the actual author-query FASTA, the complete merged12-column TSV and one actual search execution receipt, plus1..250 distinct declared versioned accessions and a contained destination. It requires typed search exit0, an empty owned group, no remaining owned processes and finite known elapsed time before publishing any shard. The caller remains responsible for proving actual OS ownership/closure and the upstream command/query/output association. The splitter verifies the supplied artifact hashes and recorded success fields; it cannot establish OS facts on its own.

The inventory uses the actual `accessionΩgene` query identifiers. Duplicate/unknown headers, missing declared genomes, unknown result query IDs and malformed numeric fields are errors. No KO filter, row deduplication, float rounding or target-ID rewriting occurs. Each shard retains all12 original field strings, row order within that genome and multiplicity; output line endings are LF. Multiple/tied hits remain intact. Query FASTA bytes are never rewritten.

A search with no reported hits is represented explicitly by a zero-row shard only after successful search/group closure. This is not a QC failure, unresolved search or defence-system negative. Every declared genome must still have a nonempty actual query inventory. The splitter performs no ML or genome acceptance.

Publication reserves a new destination, atomically creates individual shard files without overwriting, then publishes `commit.json` LAST. A partial output has no authority and cannot automatically resume or be overwritten. Successful resume requires the externally retained exact commit SHA and re-verifies all input/execution/shard bindings and the exact output inventory. Staging files remain under the project for recovery inspection. Consumers must use only a verified parent commit, never discover raw shard files by directory presence.

The parent commit binds ONE global search execution and its elapsed debit. Shards carry the parent search-binding ID and contain no invented per-genome execution/debit receipts. A future minimal V2 extension would create one stock-author merged query, run one owned search, invoke this splitter, then feed each verified shard and its own unchanged FAA into existing serial stock-resume and own-feature functions. Search time is charged once globally; each genuine per-row model/validation unit retains its own debit. That future producer/ABI/lifecycle and any empirical comparison require separate source review and bounded measurement; this preparation is not another gate for the currently running19-genome serial queue.

Ten toy fixture groups cover malformed/unknown/duplicate inputs, full fields/ties/duplicates, distinct float spellings, explicit no-hit, failed/unknown/live searches, exact resume/no overwrite, interrupted publication and containment/hash changes. They use only new toy files under project/work, no real FAA/query/TSV, models, image, WSL process or external service.
