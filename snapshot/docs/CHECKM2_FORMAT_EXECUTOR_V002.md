# Held 04R2 format-control executor

This new source implements one DNA wrap61 control after the root-accepted recovered method baseline. It preserves the original twelve pilot sources, the failed 31-artifact run and the separately validated posthoc chain. It creates no launch admission, real variant, FAA, scientific process or comparison result during preparation.

`metadata/checkm2_protein_format_input_plan_v002.json` is an immutable original-input/61-column recipe, including the accepted baseline chain, exact source manifest and limits. Its derived fields intentionally remain null. Root admission binds this stable plan SHA **before** variant generation. Only the single admitted/claimed run creates new bytes and seals their actual SHA and ordered header/sequence semantics in `semantic_identity.json`; the feature request keeps the original admitted plan SHA. No-op transforms stop without another perturbation or retry.

The native entry is an absolute Windows invocation of the bundled Python with `scripts/checkm2_format_native_v002.py --input-plan <absolute plan> --input-plan-sha256 <SHA>`. It requires a separate root-created `state/checkm2_protein_format_protocol_ready_v002.json` matching `metadata/checkm2_format_protocol_admission_template_v002.json`, with both focused GOs, source/plan/root-baseline bindings, one allowed attempt and the standard monitor gate. The checked-in template is deliberately not admitted. The native controller acquires the common launcher/installer leases, retains the actual WSL process handle/exit and atomically claims one control. A second Linux claim and common compute lease protect the only variant/science path.

The versioned image entry is derived from the accepted v001 wrapper, with separate request/state/output/namespace routes, the new plan gate and inner command. It uses the same read-only image/effective runtime and proven private short IPC helper. The unchanged original ProdigalRunner handles the new `<accession>.fna` sequentially and model-free. The selected `<accession>.faa` bytes, all ten return values, all nine mapped measurements and independent DNA sidecars must already match the baseline before protein prediction. GFF/FNA deletion by the original author is neither intercepted nor patched.

Stock prediction keeps `--genes --extension faa --threads 1 --lowmem --dbg_vectors --debug`, explicit unchanged DB and durable scientific scratch. Original author/model/DB/image/effective-runtime hashes and prediction flags must match the baseline. The new generic v002 validator runs only after observed quality exit0/group closure, under the **remaining** second unit budget, with hash-first trusted-pickle admission, exact prefix/runtime checks and no ML imports. Its 21,241 ordered inputs, 22 exact FAA metadata values and all 1,220 independently recomputed memberships retain the accepted corrected domain/algorithm. No author DNA report columns are fabricated.

Annotation has 600 seconds; protein prediction plus corrected validation together have 600 seconds. The accepted unchanged `run_unit` supplies summed group RSS <=2 GiB, Linux available >=1 GiB, at most two affinity CPUs, STOP checks, actual process creation identities, terminate/kill cleanup and terminal receipts. Native/installer/Linux compute leases, 40 GiB volume reserve and no stock resume/force/retry remain. Runtime initialization and final sealed-image verification retain their distinct bounds. Helper and native outer waits are finite; missing closure never becomes success.

`state/stages/04.json` is published before the admitted worker and every two seconds with the actual native Windows PID/birth/full command, operation and control counters. The dedicated format progress/launch files remain separate. The native result is explicitly pending **external** observed owner exit and comparison. It never attests its own future exit0 or marks whole QC completed. After the retained external owner proves actual exit0, unit/group/namespace/image closure and released common leases, `checkm2_format_compare_closed_v002.finalize(...)` can run within that owner's bounded file-only supervision. It verifies the proof/manifest/bindings, compares the full canonical row, the five-column report (0.01 percentage-point score tolerance), exact annotation/DNA evidence and all twelve DIAMOND strings as a duplicate-preserving row multiset. Missing-both features/hits, reused baseline evidence and absent closure are not evaluable. Final PASS is a separate diagnostic record; stage04 becomes `PENDING_BENCHMARK` and production/panel acceptance remains false.

The external comparison function has no dispatcher/CLI. Its owner must supply `FORMAT_CONTROL_NATIVE_GROUP_NAMESPACE_IMAGE_LEASE_CLOSED` proof with the exact current native owner, actual native/WSL exit0, all current group/runtime/image/lease/source checks and input-plan/protocol/execution hashes. Root controls the one-shot launch admission after source review; the existing monitor does not launch workers.
