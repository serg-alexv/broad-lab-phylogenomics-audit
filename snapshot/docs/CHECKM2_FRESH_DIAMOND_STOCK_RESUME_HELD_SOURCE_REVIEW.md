# Held source design: separate fresh DIAMOND from resident CheckM2 models

This is one bounded fallback design, not an implementation or permission to switch the active S1 series. Root 88832 and the current S1 worker retain compute ownership. No FAA, pickle, model, executable, namespace, probe or network was accessed for this review; only pinned source, existing review notes and small source metadata were read. Current 58 sources, Ready and stage04 remain unchanged.

The single primary fallback candidate is a fresh two-stage route for an independently admitted **unstarted** accession: original model-free DiamondRunner at unchanged settings, followed only after it closes by stock `--genes --resume` on exactly its newly completed artifacts. It retains one query genome per DIAMOND call. It does not use the failed T1 partial TSV, replay a completed S1 row or turn a failed/pending row into success. A prior failed S1 prediction is not an unstarted row and is outside this design without a new explicit exception/claim.

The static CheckM2 import closure rooted at `diamond.py` contains diamond, defaultValues, fileManager, keggData, sequenceClasses, versionControl, version and zenodo_backpack. It imports pandas/requests/tqdm but contains no explicit main/predictQuality/modelProcessing/Keras/TensorFlow/LightGBM import in that author-module closure. This is not a measured runtime import/memory proof; the future direct entry must verify actual module origins and absence of model modules. `main.py:28` imports predictQuality before parsing the CLI; predictQuality imports modelProcessing, which imports Keras with the accepted TensorFlow backend. Therefore invoking the normal CLI, even before a prediction, is not a model-free DIAMOND entry. `prediction_wf:87` loads boosters, NN and scaler regardless of resume mode.

The model-free entry would call the unchanged DiamondRunner constructor with threads 1, lowmem=true, the immutable explicit database and a new owned output directory, then its public run method on one exact accepted FAA. No Predictor/main/effective CLI bootstrap or author patch is used in that phase. The constructor checks `diamond help`; run invokes the original DIAMOND binary/search command and creates `diamond_output/DIAMOND_RESULTS.tsv`. Required unchanged options are outfmt 6, max-target-seqs 1, threads 1, query-cover 80, subject-cover 80, id 30, evalue 1e-5 and block-size 0.5, with the same DIAMOND 2.1.11 binary and CheckM2 database. Numeric block-size controls below 0.5 are not exposed by the stock CheckM2 CLI and are outside this design.

A concrete asymmetry matters: direct DiamondRunner has no `--tmpdir` parser and calls `tempfile.gettempdir()`, requiring at least 500 MiB free. The private 32 MiB `/tmp` alias is intended for short IPC, not these durable biological temporaries. Its direct entry must set its process-local `tempfile.tempdir` to a newly created durable project temp directory before run; no global temp setting changes. The subsequent normal CLI stage still needs the accepted same-process short-IPC prewarm before main's `ChangeTempAction` points ordinary temp files at its durable project directory.

Required fresh per-accession layout:

| Path below a new owned root | Requirement |
|---|---|
| input/ACCESSION.VERSION.faa | Copy of the exact accepted FAA, original bytes/ordered protein IDs and SHA |
| resume_output/protein_files/ACCESSION.VERSION.faa | Same FAA; exact inventory contains one regular FAA and no sidecars/subdirectories |
| resume_output/diamond_output/DIAMOND_RESULTS.tsv | Only the new successful original-runner output; no stale/extra matching filenames |
| durable_tmp/stageA and durable_tmp/stageB | New durable project directories, separately controlled from short IPC |
| phase receipts/manifests outside those two input inventories | Actual commands, identities, typed exits, group closure, timings, raw SHA256/bytes and source/runtime/database/options bindings |
| resume_output/feature_vectors_1.pkl and quality_report.tsv | New stock stageB outputs, kept separate from all older outputs |

The FAA basename is essential. Normal `--genes` copies an extensionless protein file named ACCESSION.VERSION, whereas metadata.py uses `splitext(basename)[0]`. Reusing that extensionless copy during resume strips the version. Fresh staging must retain `.faa`, so original DIAMOND prefixes and resumed metadata both use ACCESSION.VERSION. FASTA primary protein IDs are the first header token; original DiamondRunner prefixes them with ACCESSION.VERSION plus the exact `Ω` separator. Do not rewrite IDs/headers or deduplicate hits.

A stageA gate needs actual typed exit0, empty owned process group and an atomic closed-file manifest. Validate raw outfmt 6 as twelve fields with parseable finite numeric fields/valid identifiers, retaining all multiplicities; the source consumes the first two fields and counts returned rows. Query prefixes must map to this exact FAA and each primary protein ID; target annotation must split into the original reference/KO fields. Out-of-feature KO values are filtered by stock code and must not be reclassified manually. No assumption of one row per query or forced deduplication is justified by this review. Empty, malformed, truncated, mismatched, unclosed or old output is not reusable. Stock resume itself checks filenames/existence, not this provenance or completeness.

For stageB the input remains that same single FAA; use the same accepted bootstrap/overlay, private read-only image/database, source hashes and options as S1, adding only the explicitly reviewed `--resume`. main.py skips output-directory emptying in resume mode. predictQuality.py:95–112 lists existing protein_files and skips gene calling; :127–135 lists DIAMOND_RESULTS files and skips the search. It still creates DiamondRunner/checks help, recalculates AA metadata, reconstructs KO/pathway/module/category features, loads/applies all models/scaler/reference data, selects a model and writes the report. There must be no extra files in either inventory, and no `--force` or update/config write is needed. Explicit database integrity is a gate: do not allow a failed explicit database check to fall through to a default configured location.

Downstream data/model semantics stay unchanged: 20 amino-acid counts, AALength and CDS plus 19,999 raw KO counts, 416 pathways, 757 modules and 47 categories total 21,241. Pathways/categories use clipped presence; module values use raw counts/original denominators and may exceed1, with duplicate/missing definitions handled exactly as stock source. Full ordered float features enter fixed boosters/scaler; the NN uses the first 20,021 scaled values with a singleton channel, and the fixed-reference cosine selector uses each query's own AALength/general/specific outputs. No query-cohort fitting is introduced. `--genes` preserves the five-column protein report, not nine nucleotide report columns; original ten caller values and separate DNA sidecars remain bound. Validate each new result with own 22 FAA values, all 21,241 finite/domain/order features, independent 1,220 memberships and its own canonical row/report. Never compare different genomes with Abiotrophia's row hash.

Source compatibility is conditional. Keeping the exact original runner, one-FAA scope, options, database and resume parser avoids an author algorithm patch, but no empirical hit/numeric invariance or memory saving was demonstrated here. The source's residue/feature generation order and top-hit behavior must not be changed. This route shifts DIAMOND away from resident ML and adds another process/staging/checksum boundary; it is not established as faster or able to fit 2 GiB.

Before any switch, require the actual S1 closure/resource/lease handoff and a frozen accepted-row map. Preserve valid S1 prediction/feature/commit receipts and reuse them only after independent external closure acceptance; remove those accessions from the new unstarted work list without replay. Preserve original failure/once-claims and source/taxonomy/three hold masks. A new isolated recipe/source manifest/claims and explicit Root admission are required because S1 currently forbids stock resume and permits only one prediction per accession. Current 58 source or live dispatch must not be changed in place.

The time ceiling is not a fresh 3495.758365 seconds: derive R from that original new-S1 allowance minus every actually spent S1 quality/validation unit, successful or failed, before handoff. Unknown elapsed or closure blocks. For each unstarted genome, all model-free DIAMOND, stock-resume inference and independent validation elapsed share at most min(600 seconds,R); every stage receives only the remaining part and commits its debit before another can start. Mount/cold-session overhead needs a separately stated finite wall deadline and cannot create new scientific time. Keep 2 CPU/2 GiB summedRSS/1 GiB Linux headroom/40 GiB reserve unchanged. First failure stops; no automatic retry, fallback, resource increase, smaller block or second model call. No full-ten bulk benchmark, next20 or panel acceptance follows from this source design.
