# Bounded OCI model-source review, 2026-10-27

No author-verified complete PADLOC/DefenseFinder model archive was established by this review. The full-catalog gate remains held. Public Quay registry metadata can be inspected through HTTPS without a Docker engine, but program-image availability does not establish model presence, completeness, provenance or compatibility.

The review read the existing acquisition audit first and then queried only small public documentation, DockerHub repository metadata, Quay manifests and two 3,449-byte image configurations. It downloaded no filesystem layer, model, genome or tool package and ran no image, updater, installer or prediction. Native requests rejected automatic redirects; the two config redirects were followed manually only after checking the official `cdn01.quay.io` host, exact digest path and expected 3,449-byte size. GitHub/ghcr links were retained as metadata where supplied by primary sources and were not opened or followed.

No inference of model absence is made from this limited view. The [BioContainers integration documentation](https://biocontainers-edu.readthedocs.io/en/latest/conda_integration.html) describes automated containers from Bioconda packages; these records do not establish author endorsement of a bundled defense database.

DockerHub metadata queries for the author-named `mdmparis` and `padlocbio` namespaces returned empty public repository listings. Searches also identified `bjhall/defense-finder`, `naveendockr/defense-finder`, `jinlongru/defensefinder`, `mesti90/defensefinder`, `multifractal/defensefinder` and `yuxiangtan/padloc`. Their publisher-to-author relationship and complete model provenance were not verified. The [yuxiangtan repository metadata](https://hub.docker.com/v2/repositories/yuxiangtan/padloc/) explicitly says its database is excluded; it therefore cannot supply the required model archive. A repository description containing an upstream URL is not authorship authentication. The similarly named `padloc/server` password-manager image is unrelated and excluded.

The [DefenseFinder authors' PyPI documentation](https://pypi.org/project/mdmparis-defense-finder/) treats model retrieval separately from program installation and identifies its program license as GPLv3. This does not license an uninspected image's model contents. The [author webservice](https://defensefinder.mdmlab.fr/) separately advertises program2.0.0/models2.0.2; neither those labels nor the Quay program3.0.0 tag establishes mutual compatibility. The [PADLOC author site](https://padloc.otago.ac.nz/padloc/) identifies DB2.0.0 and distinguishes candidate systems. These author sites did not supply an authenticated DockerHub/Quay complete-model release in the inspected material.

Precise blocker: an author-endorsed registry reference tied to a pinned, complete model catalog, exact model paths/release/file checksums, compatible tool/model versions and original model licenses/notices is still missing. No large layer acquisition is proposed on the evidence available. Any future archive must pass those source gates and independent profile/definition/positive-control checks before prediction. Legacy PADLOC1 remains a separate held candidate, lacks RM/Cas in the earlier inventory, and cannot clear this gate. No defense unknown/not-run state becomes a negative call.
