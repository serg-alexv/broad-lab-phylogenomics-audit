# Held ten-genome protein benchmark strategy

Use the existing immutable ten-genome plan unchanged: ten genera across five families, including its three ancillary metadata-review genomes. Their source/metadata holds and context-only NCBI scores remain intact regardless of any new prediction. This is a method/resource benchmark, not a panel or biological-truth acceptance.

The primary strategy is ten sequential, separately committed original ProdigalRunner annotation units, followed by **one stock protein-input batch of exactly ten** (`--genes --extension faa --threads 1 --lowmem --dbg_vectors --debug`). Stock DIAMOND and feature chunks are 250; ten fits one chunk. The pretrained scaler, fixed-reference cosine calculation and per-query model selection do not fit across the cohort. One invocation avoids ten model/database initializations. This is source support for batching, not a measured memory guarantee: cosine matrices and neural activations grow with query count, so the unchanged hard gates remain decisive.

Budgets must be separately admitted: each annotation retains 600 seconds, at most ten units/6,000 seconds total; the single batch **prediction plus all feature validation shares a proposed 3,600 seconds**. The maximum declared scientific-unit allocation is therefore 9,600 seconds. This replaces no existing file and is not a silent reuse of the old threads-2/600-second ten-genome template. Keep two affinity CPUs, stock threads 1, 2 GiB summed group RSS, 1 GiB Linux headroom and 40 GiB volume reserve. A resource stop holds the batch; it does not trigger an automatic split, retry or raised budget.

Reuse accepted runtime/model/database assets, acquired genomes/receipts and accepted source/DNA QC. Reuse an existing FAA only if its exact source/binary/automatic-table/options/ten-return/DNA-sidecar manifests and observed closure prove the same method. Such reuse has not been established for the cohort here. The accepted Abiotrophia baseline is absent from these ten and is not added by default. Only a concrete reviewer-identified comparability need could justify a separately admitted eleventh bridge row using its already accepted FAA; that would not change benchmark membership or supply biological truth.

The implementation needs a thin new multirow validator, not a modified one-row helper. Require one trusted raw dump with ten unique expected Names and 21,242 exact ordered columns; validate 21,241 finite numeric features, 22 FAA metadata values and 1,220 recomputed memberships per row, preserving raw module means and clipped pathway/category semantics. Record each accession's canonical float64 row hash, exact caller evidence, five-column report and complete DIAMOND provenance. Missing/failed rows stay unresolved. All three ancillary holds survive any measured score.

Make genuine resume barriers explicit. After each observed exit-zero/empty-group annotation, atomically commit the FAA, ten returned values, DNA/source sidecars and SHA256 manifest. After the single prediction closes successfully, commit its complete raw outputs before validation. An explicitly authorized continuation may reuse only exact committed units and remaining budgets; interrupted partial outputs are not stock `--resume` checkpoints. A complete prediction may support a separately admitted file-only recovery without another ML run. Preserve unknown exits, enforce STOP ownership, prove descendants/image/leases closed and never clear user STOP automatically. Test these boundaries before dispatch; no automatic retry or unknown-as-negative is allowed.

The strategy remains HELD until the format control has actual PASS/full closure and root acceptance, followed by reviewed cohort sources, an explicit finite-deadline admission, live stage04 registration and fresh resource/lease/STOP checks. No real input, FAA, variant, scientific runtime or execution admission was created by this preparation.
