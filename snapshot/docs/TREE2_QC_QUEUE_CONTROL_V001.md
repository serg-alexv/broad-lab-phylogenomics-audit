The queue controller is a file-only helper for the one local Root. It never launches a scientific process, imports the scientific runtime, reads a genome/FAA/pickle/model, calls an AI, admits an experiment or turns unknown results into negatives. The immutable canonical inventory and its source eligibility remain distinct from completed QC and final panel/taxonomy acceptance.

The fixed active intent path is `state/qc_campaign_queue_v1/intent.json`. Root enables a new copy of `metadata/tree2_qc_campaign_intent_TEMPLATE_v001.json` after reviewing its source/queue bindings. The template itself is disabled. The single persistent event dispatcher invokes the helper's `next` operation before each meaningful event model call and appends the returned immutable proposal path/hash to that short prompt. Ordinary OS waiting does not invoke this helper or a model. Active controller code and prompt/config hashes are not rewritten by the helper.

The operation interface is:

```
python -B scripts/checkm2_bulk_queue_control_v001.py --project-root ROOT --intent state/qc_campaign_queue_v1/intent.json --intent-sha256 SHA next
```

`next` atomically publishes an immutable proposal and `state/qc_campaign_queue_v1/pending_intent.json`. Its compact stdout contains `proposal`, `status`, `action` and `queue_ids`. It neither reserves inputs nor creates a scientific execution claim. Identical queue and ledger head yield the identical proposal. The initial real inventory selects `REPAIR_CURRENT_P20`: one saved validation plus19 reserved inputs in their original P20 order. It must reuse the three already completed upstream phases and retained prior budgets/claims. Only after an accepted closed repair does the policy offer new cohorts of at most20 `READY_FRESH_QC` source-supported inputs in frozen species-balanced order. Accepted results, source-held/excluded/missing inputs and historical donors requiring review cannot become fresh jobs.

Before building/admitting that cohort, Root invokes `reserve` with the returned proposal artifact using `--artifact PATH --artifact-sha256 SHA --artifact-bytes N`. This records only an exclusive logical planning reservation in a hash-chained immutable ledger and creates a bound launch context. The context contains `queue_intent`, `canonical_QC_queue`, `queue_proposal`, `queue_reservation` and exact IDs. New scientific launch producers include those fields in their immutable launch receipt alongside the required canonical `native_owner` exact identity; any optional identity alias must match it. Existing dispatcher exit events already bind the launch receipt, so the queue context travels to subsequent Root turns without a second controller. A missing launch-context file can be reconstructed from its committed reservation without a new claim or scientific invocation. An incomplete ledger/head transaction stops for evidence reconciliation.

After actual scientific validation and full process/group/namespace/image/lease closure, Root writes a separate authority with schema `TREE2_ROOT_QC_QUEUE_COHORT_CLOSURE_V001`. It binds the queue SHA, exact original proposal SHA and ordered IDs, preserves prior claims/debits, and includes bound `closure_and_result_evidence`. `ROOT_ACCEPTED_CLOSED_COHORT_FOR_QUEUE_ADVANCE` requires an actual typed cohort-worker native exit0 and validated method artifacts. These fields describe the scientific/file-only validation worker, not a CLI teardown exit. Computationally valid low-quality genome estimates may be recorded as QC rejections; this authority does not erase source/taxonomy/quality masks or imply every genome passes eligibility.

Root calls `close` with that authority artifact using the same three artifact arguments. The function commits acceptance and immediately calls the next-proposal hook in the same transaction sequence. No manual chat reminder is involved. Repeating the exact accepted authority is idempotent and cannot repeat the cohort. A closed failed cohort instead produces a repair intent and blocks fresh selection until Root accepts its bounded repair. That acceptance must bind the exact prior failed authority and explicitly assert `repaired_without_replaying_accepted_phases:true`; normal pipeline source/runtime/resource/admission gates remain mandatory. A planning reservation never constitutes that admission.

After fresh cohorts, eligible historical donors receive `REVIEW_HISTORICAL_RESULTS_REUSE_ONLY`. Their review may be reserved and closed without upstream recalculation. When no runnable or unresolved work remains, the helper first requires `VERIFY_CURRENT_ACCEPTED_REGISTRY_AND_CLOSED_RESULTS`; it does not infer completion from an empty list. Root's `finalize` authority uses schema `TREE2_ROOT_QC_QUEUE_REGISTRY_RECONCILIATION_V001`, binds the current registry and ledger head, exactly covers every source-supported queue ID, includes bound actual closure/validation evidence, and preserves source/taxonomy/unknown masks. Only then is `ELIGIBLE_QC_QUEUE_EXHAUSTED_WITH_EXPLICIT_MASKS` emitted. That state is never full-tree, representative-tree, final-panel or defence completion.

Source-only verification: twelve synthetic metadata fixtures passed. They cover repair priority, original P20 order, accepted-event auto-next, duplicate/idempotent claims, exact failure repair linkage, unknown exits/validation veto, masks and accepted no-replay, partial ledger failure, unknown state rejection, metadata reconstruction without a claim, and final registry/scope reconciliation. A separate metadata-only read verified the real1179-row canonical queue and its initial exact20-member repair proposal. No real intent, ledger, process, scientific unit or runtime ownership was created during source preparation.

Every ledger read rebinds each stored proposal, Root closure authority and its closure/result evidence. Mutation or deletion stops advancement; a preserved event boolean cannot substitute for current hash verification. The peer-requested narrow tamper/delete fixture confirms this stop boundary.
