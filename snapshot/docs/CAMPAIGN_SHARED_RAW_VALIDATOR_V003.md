# HELD shared-search raw validator V003

`checkm2_campaign_index8_shared_validate_v003.py` implements the future shared raw-search validation interface. It does not launch a search, import a model, compare controls, or authorize a campaign. The active V2 workflow remains separate.

The five required arguments are `--request`, `--request-sha256`, `--output`, `--binary-execution`, and `--binary-execution-sha256`. The common V003 gate owns plan, admission, source, resource, selected-input and accepted-control authority. The validator requires the exact accepted runtime and a single observed `unit_shared_diamond` execution with typed exit 0, known elapsed time, an empty owned group, and the same PID, boot identity and creation ticks as the producer before its replacement by DIAMOND.

The producer receipt must be `search_exec_prepared.json` beside the requested validation output. Its bound FAAs, query order, original annotation associations, database, binary, scientific arguments and source origins must agree. The merged query must contain exactly the original primary protein IDs and sequences, in the original order, prefixed with each versioned accession and `Ω`. Duplicate or ambiguous keys are rejected before a dictionary overwrite can conceal them.

The raw file is `request.search_output/diamond_output/DIAMOND_RESULTS.tsv`. The validator checks every original twelve-field row, finite numeric domains, own query keys and nonempty `reference~annotation` targets. It retains annotations outside the model KO list. It calls the existing lossless splitter once, preserving original field strings, query association and duplicate multiplicity. The split commit refers to one genuine global execution and debit; it creates no per-genome binary exit receipts or additional search debits. A successful search shard without reported hits remains explicitly distinct from failed, unknown, or biological absence.

The output status is `GLOBAL_SHARED_SEARCH_SPLIT_VALIDATED_PENDING_UNIT_CLOSURE`. It binds `split_commit`, `merged_query`, `merged_raw`, `query_inventory`, `selected_faas`, the producer receipt and the actual binary execution. `query_inventory.json` and `shards/` sit beside the requested output. Existing output, inventory or shard directories are refused rather than silently retried or overwritten. All source FAAs, annotation receipts, annotation units, annotation commits, query, raw file, prepared receipt and binary execution are rechecked before publication.

Control equality is deliberately deferred: the first fresh genome's own model and feature checkpoint must precede the separate control-comparison unit. This module establishes neither model accuracy, biological eligibility, memory fit, speedup nor single-query numerical equivalence. Those remain later measured gates.

Seven fixture groups passed using tiny synthetic files and extracted pure functions. They cover typed execution and creation identity, namespaced query order and sequences, ambiguous keys, missing/extra/reordered queries, all twelve original fields and duplicate conservation with one debit, empty-control non-negative semantics, malformed targets/numerics, and the absence of control/model dispatch in the production function. The fixtures import only the existing standard-library splitter; they do not import the target's common/provider/runtime/scientific modules or read real FAAs or TSVs.
