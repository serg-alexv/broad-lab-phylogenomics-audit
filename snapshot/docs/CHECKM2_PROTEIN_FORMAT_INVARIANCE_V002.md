# Held protein-pipeline format control, v002

This template preserves v001 and the twelve executed pilot sources. It binds the corrected feature schema `90e48251…` and describes a future baseline chain through the saved-output posthoc pointer, validation, execution, manifest, native/lease closure and explicit root acceptance. Every successful-chain hash remains null. The original failed attempt has no successful `result.json` requirement and remains unchanged; its original outer exit stays unknown. A target validation record may retain `PASS_PENDING_CLOSURE`, provided the surrounding current execution and native/root acceptance chain is independently proved.

The control remains exactly one 61-column DNA rewrap with LF line endings, preserving original headers, record order, sequence bytes and case. Original acquisition is untouched; derived bytes must differ. A no-op or failure stops the control without another perturbation or retry. No genome, variant, FAA, model, saved pickle or actual baseline output is opened or generated during this preparation.

The same unchanged original sequential caller and stock protein route must produce identical selected FAA bytes and ordered proteins, all ten returned values and separate DNA metrics. The original deletion of GFF/FNA remains intact. Corrected validation must require all 21,241 finite ordered features, all 22 FAA metadata fields and all 1,220 independently recomputed memberships, then compare the full canonical float64 row hash. The DIAMOND evidence is a full twelve-column multiset that keeps duplicate rows and ignores only row order. Missing evidence, even on both sides, is not evaluable. The five stock report columns retain exact Name/model/notes and the existing 0.01 percentage-point completeness/contamination tolerance.

The pure v002 receipt adapter reuses the existing v001 annotation and report comparators unchanged. It requires a separate closed-execution/root-authority attestation for each role and rejects substituting the baseline as its own control. Those attestations do not replace the future owner's actual file, manifest, source, runtime, input and lifecycle verification. The adapter performs no file I/O and cannot dispatch work. Existing rewrap and DIAMOND digest functions are pinned for later use but are not called now.

There is no runnable execution adaptor in this proposal. The frozen pilot executor invokes the failed v001 feature validator; directly reusing it would repeat that defect. After root accepts the final baseline chain, a separate versioned executor can reuse the validated sequential caller and stock CLI while routing feature validation through the corrected narrow interface. The template freezes that interface and distinct output/progress/STOP routes without modifying bound sources or building a new execution framework.

Before a future control starts, its owner must bind the successful baseline chain, prepare the derived input only after root baseline acceptance, obtain a new source-reviewed control admission, register live progress, verify fresh common leases and respect all STOPs. Limits remain two CPUs, 2 GiB summed group RSS, 1 GiB Linux headroom, 40 GiB volume reserve, a 600-second annotation unit and a second 600-second unit shared by protein quality and feature validation. One attempt is allowed, with no stock resume, force or automatic retry. This tests pipeline invariance and provides no independent biological truth, nucleotide-mode numerical equivalence or production acceptance.
